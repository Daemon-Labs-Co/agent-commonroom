# Separate task contracts from execution records

Retained detailed reference. Start with [user guides](../../../user/README.md) for illustrated
steps or [technical contracts](../../README.md) for concise current interfaces. Historical
observations remain historical; documented security requirements still apply.


A task definition is a versioned seven-part contract; actual bound inputs,
attempts and returned outputs belong to append-only execution records. Finite
output types and structurally validated immutable values replace free-form
completion claims, while file/bundle execution refuses until independent storage
custody can prove the actual object; accepting a model's path would erase the
very distinction the contract is intended to establish.
